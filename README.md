# ВОООЗ

Telegram Mini App для знакомства с вузами России: выбор города, поиск и фильтры, подробные карточки, избранное, анкета ЕГЭ, поиск специальностей и предварительный тематический подбор. Интерфейс адаптирован для телефона и обычного браузера. Макет из PDF переработан в светлый интерфейс с зелёными акцентами.

Готовый адрес GitHub Pages появится в этих настройках после публикации. Сайт пока не считается опубликованным: включение Pages и доступность URL не подтверждены.

## Открыть без установки

Для просмотра и проверки интерфейса соберите автономный HTML:

```sh
npm run build:standalone
```

Откройте полученный `standalone/voooz.html` в браузере. В одном файле находятся приложение, каталог, стили, шрифты и фотографии. Для выбора города, избранного, карточек, анкеты ЕГЭ и предварительного подбора не нужны Node, сервер или подключение к интернету. Для перехода на официальный сайт вуза нужен интернет. Это версия для просмотра, а не размещённый Telegram-бот.

Исходный корневой `index.html` — вход для Vite. Его нельзя открыть отдельно во встроенном просмотрщике: он ссылается на исходные модули и API сервера. Для самостоятельного просмотра нужен именно собранный `standalone/voooz.html`, а для разработки — команды ниже. Автономная и серверная версии используют общую логику `shared/catalog.mjs`; проходные баллы и бонусы за достижения не выдумываются.

## Локальный запуск

Нужен Node.js 22.12+ (проверено на 24.19) и npm.

```sh
npm ci
npm run dev
```

Vite запускает интерфейс на порту **5173**, Node API — **3001**. `/api` проксируется автоматически. Секреты, базы данных и внешние сервисы для основного сценария не требуются. Если домашний npm-cache недоступен, используйте `npm --cache /tmp/voooz-npm-cache ci`.

```sh
npm test        # сервер, данные, валидация, Telegram launcher
npm run build   # production-сборка
npm start       # собранное приложение и API на PORT, по умолчанию 3001
```

Сквозные браузерные проверки: `npm run test:e2e`. Если Chromium не установлен, выполните `npx playwright install chromium`. На этой облачной машине используется `/usr/bin/chromium`; другой путь задаётся через `CHROMIUM_PATH`.

## Подключение к Telegram

Приложение использует локально собранный Telegram Web App SDK: `ready`, `expand`, цвета окна и кнопку «Назад». В обычном браузере те же экраны работают без Telegram. Данные анкеты и избранное сохраняются в `localStorage` этого устройства; при подборе анкета отправляется серверу. Учётной записи и межустройственной синхронизации пока нет. Публичные API не используют Telegram-профиль для авторизации; перед добавлением личных кабинетов потребуется серверная проверка `initData`.

1. Разместите production-сборку и Node-сервер на хостинге с **публичным HTTPS**. Приложение и API должны быть на одном origin. Можно использовать приложенный Dockerfile; порт контейнера — 3001, проверка работоспособности — `/api/health`.
2. Создайте бота через @BotFather. Добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBAPP_URL` в секреты хостинга либо в локальный игнорируемый `.env` (образец — `.env.example`). Не коммитьте токен и не передавайте его во фронтенд.
3. Запустите отдельный процесс `npm run bot`. Он настраивает команды, кнопку меню и отвечает на `/start` кнопкой открытия Mini App. Для долгой работы нужен менеджер процессов хостинга. Используется long polling; одновременно должен работать один экземпляр, без конкурирующего webhook.
4. Проверьте `/start`, выбор города, анкету и переход на официальный сайт в мобильном Telegram. Реальная Telegram-сессия ещё не проверялась: токен и адрес опубликованного приложения не предоставлены.

Для бота серверу нужен HTTPS-доступ к `api.telegram.org`. Никакие сообщения реальным пользователям при разработке не отправлялись.

## Каталог и ограничения

Состав и источники перечислены в [data/CATALOG.md](data/CATALOG.md). Встроены реальные наименования и сайты вузов/филиалов, города, редакционные описания ведущих вузов и направления бакалавриата/специалитета с кодами и поисковыми синонимами профессий. Это **стартовый справочник**, а не полный действующий реестр. Старые записи филиалов отдельно помечены годом снимка и необходимостью проверки. Список не является официальным рейтингом.

Подбор без нейросети учитывает тематику предметов и интересов. Он не знает действующие конкурсные группы, реальные проходные баллы, бюджетные места и вероятность зачисления. Сумма ЕГЭ вычисляется точно; бонусы за достижения намеренно не прибавляются общей формулой. Для них, олимпиад и вступительных испытаний нужны правила конкретной программы и года. Проходной балл прошлого года не гарантирует поступления.

Для ведущих вузов добавлены реальные локальные фотографии с атрибуцией в [data/photo-sources.json](data/photo-sources.json) и манифестах `data/photos-*.json`. У записей, для которых снимок ещё не найден, остаётся иллюстрация. Каталог фотографий и действующий реестр продолжают пополняться. Из-за ограничений сети официальные сайты и Wikimedia не были доступны для онлайн-сверки; перед публичным размещением изображений следует подтвердить исходные условия их использования.

## Нейросеть: бесплатная локальная Qwen

По выбору пользователя основной провайдер теперь **Qwen 2.5 0.5B через Ollama**. Платы за запросы и API-ключа нет. Модель работает на компьютере/сервере владельца приложения; посетителям сайта не нужны Ollama, VPN или собственные ключи. Вычислительные ресурсы хостинга оплачиваются отдельно, если сервер арендуется. Автоматического перехода на платный API нет.

Для быстрого запуска на сервере с Docker Compose:

```sh
docker compose up -d --build
docker compose logs -f model-init
```

`compose.yaml` запускает приложение на порту 3001 и внутренний Ollama, скачивает `qwen2.5:0.5b` отдельной задачей `model-init`, хранит модель в постоянном Docker volume. Порт Ollama не публикуется; облачные модели отключены через `OLLAMA_NO_CLOUD=1`. Для открытого сайта перед портом приложения нужен публичный HTTPS. До завершения загрузки модели приложение показывает каталог с понятным статусом. `docker compose config --quiet` проверен; сами контейнеры в этой среде не запускались.

Если Ollama установлен обычным официальным установщиком Windows/macOS/Linux:

```sh
ollama serve
ollama pull qwen2.5:0.5b
npm run dev
```

Если приложение Ollama уже запущено, второй процесс `ollama serve` не нужен. На Linux для воспроизводимой установки без `sudo` доступны `npm run ai:install`, `npm run ai:serve`, `npm run ai:pull`, `npm run ai:check`, `npm run ai:smoke`: см. [docs/OLLAMA_RUNTIME.md](docs/OLLAMA_RUNTIME.md). Помощник поддерживает Linux AMD64, проверяет опубликованный SHA256 официального релиза, оставляет только CPU runtime и хранит веса в игнорируемом каталоге. Для облачной среды выбран `VOOOZ_OLLAMA_HOME=/workspace/.voooz-ollama`.

Настройки сервера по умолчанию:

```dotenv
VOOOZ_AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:0.5b
```

Без `.env` используются те же значения. В Compose адрес — `http://ollama:11434`. `/api/health` показывает `ai.configured:true` только когда процесс отвечает и выбранная локальная модель установлена; `ollama.available` и `ollama.modelInstalled` разделяют эти состояния. Наличие установленной модели ещё не доказывает качество анализа. Настоящий короткий запрос проверяет `ai:smoke`, а итоговый пользовательский сценарий — отправка анкеты с доступными официальными страницами. На CPU ответ может занимать несколько минут; интерфейс ждёт до четырёх минут.

### Откуда берутся сведения

Локальная Qwen не имеет встроенного веб-поиска. `server/evidence.mjs` загружает официальную страницу вуза и несколько связанных страниц приёмной комиссии, убирает исполняемый HTML и передаёт ограниченные фрагменты модели. До трёх тематически выбранных вузов, девяти документов и 6 000 символов текста за один анализ. Это ограниченный обход HTML, а не полный поиск по всем вузам России: PDF, сканированные документы и сайты, требующие JavaScript, пока не читаются. Если официальные материалы недоступны, модель не вызывается для расчёта поступления; остаётся подбор по каталогу с явным уведомлением. Проверки источников подтверждают происхождение текста, а не гарантируют правильность интерпретации малой моделью. Подробности: [docs/EVIDENCE.md](docs/EVIDENCE.md), [контракт Ollama](docs/OLLAMA_API.md).

`shared/admissions.mjs` выбирает нужную тройку ЕГЭ из всех предметов, проверяет минимумы, применяет найденные правила достижений отдельно для вуза/года и ограничивает итог 310. Учитываются места конкретной конкурсной группы и кампуса. Достижения считаются предварительно по анкете, документы проверяет вуз. Программы с подтверждёнными невыполненными минимумами или нулём бюджетных мест исключаются. Кнопка подачи появляется только для подтверждённой официальной страницы.

Произвольная вероятность от модели не принимается. Круг показывает только долю сопоставимых прошлых лет, в которые балла хватало; при недостатке данных оценка неизвестна. Методика: [docs/ADMISSIONS_METHOD.md](docs/ADMISSIONS_METHOD.md).

**Текущее состояние среды, 23.10.2026:** официальный Ollama 0.40.9 установлен, SHA256 проверен, локальный сервер отвечает HTTP 200. Модель `qwen2.5:0.5b` загружена; наличие модели и настоящий короткий JSON-ответ проверены через `ai:check` и `ai:smoke`. Запрос через API приложения с контрольным искусственным документом занял 43 секунды и вернул `ai.used:true`; неподтверждённые конкурсные сведения остались `null`. Автоматические проверки HTTP/интерфейса используют контролируемые документы и ответы; они не подтверждают качество на реальных правилах приёма. Официальные сайты вузов в этой среде пока могут блокироваться сетью, поэтому живой анализ актуальных условий ещё не считается проверенным. Скачанный автономный HTML не содержит Ollama и весов и не запускает AI самостоятельно.

Ранее подготовленные платные адаптеры сохранены как необязательные: `VOOOZ_AI_PROVIDER=yandex` ([документация](docs/YANDEX_API.md)) или `openai` для поддерживаемых OpenAI территорий. Только явный выбор включает их; ключи не нужны для локального режима. Старые поля Yandex в черновике настроек больше не являются требованиями этого сценария и могут быть удалены через редактор настроек.

## Сборка архива для просмотра

`npm run package:preview` собирает автономный HTML, формирует проверенный `downloads/voooz-open.zip` и обновляет `docs/index.html`. Для упаковки требуется Python 3 со стандартной библиотекой; он не нужен для обычного запуска приложения или просмотра архива. Чтобы сохранить отдельный номер выпуска, после сборки можно выполнить `python3 scripts/package-preview.py --version v4`.

Исходные пожелания к подбору сохранены в [docs/FUTURE_SELECTION.md](docs/FUTURE_SELECTION.md). Реализованы серверная интеграция и расчёт по источникам; живое подключение требует серверных настроек. Персональная вероятность зачисления требует отдельной проверенной модели.

## Структура

- `src/` — React, интерфейс и локальное состояние.
- `server/` — Node HTTP API, адаптер AI и Telegram launcher.
- `shared/` — общие фильтры, проверка ЕГЭ и подбор для сервера и автономного HTML.
- `data/` — локальный каталог, специальности и происхождение данных.
- `public/images/` — локальные изображения.
- `tests/` — серверные тесты и браузерные сценарии.

Работайте в существующем checkout: облачная задача уже изолирована. Создавать отдельный Git worktree для обычного запуска не требуется.

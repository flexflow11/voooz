# Баллы, источники и историческое сравнение

`shared/admissions.mjs` проверяет структурированный ответ нейросети и выполняет арифметику без внешних сервисов. Это расчёт по найденным правилам, а не статистическая модель зачисления. Само наличие ссылки подтверждает происхождение сведений, но не заменяет проверку смысла документа; актуальность правил нужно сверять с приёмной комиссией.

## Контракт программы

`validateAdmissionProgram(raw, sources, university, profile)` принимает нормализованную анкету из `validateProfile`, отдельный набор точных поисковых ссылок провайдера (`Set`) и сведения о вузе. Возвращает проверенную программу либо `null`. Ссылки, написанные моделью внутри JSON, сами по себе не становятся источниками.

Обязательны название `program`, `competitionGroup`, `campus`, `year`, `funding` (`budget`/`paid`), официальный `source`, булево `additionalTests` и `examOptions`. Каждая альтернатива в `examOptions` содержит ровно три разных `{subject, minimum}`. Предметы канонические, например `Математика`, а не «Математика (профильная)». Год правил — текущий, предыдущий или следующий; фактически выбранный год возвращается в результат.

`budgetSeats` содержит `{value, year, source, competitionGroup, campus}` на тот же год и конкурс. Общее количество мест во всём вузе не подходит. `application` содержит `{url, source}`: обе точные ссылки должны присутствовать в поисковых источниках и принадлежать официальному домену вуза. Главная страница вуза не принимается за ссылку подачи. Внешние порталы без установленной связи не угадываются; в таком случае кнопка подачи отсутствует.

## ЕГЭ и достижения

Из всех результатов выбирается наиболее выгодная полная тройка, которая выполняет минимумы программы. Дополнительные результаты не прибавляются к сумме. Максимум этой модели — 300 за экзамены и до 10 за достижения, всего 310. Программы с дополнительными испытаниями явно помечаются, полный конкурсный балл по ним не рассчитывается.

Правила достижений задаются отдельно для каждой программы и года: `achievementRules:{year,source,maxPoints,complete,items}`. Элемент: `{key,value,points,description,conditionsComplete,requiresDocuments,exclusiveGroup?}`. Поддерживаются точные значения полей анкеты `certificate`, `gto`, `sport`, `essay`. Общая отметка `true`, неполный перечень, неподтверждённый источник или невыполненные условия оставляют бонус неизвестным. Взаимоисключающие правила с одним `exclusiveGroup` учитываются по максимуму, остальные суммируются в пределах вузовского ограничения и общего потолка 10. `complete:true` означает, что найден именно полный действующий перечень, а не фрагмент страницы. Если в полном перечне нет заявленного достижения, за него учитывается 0.

`conditionsComplete:true` допустимо только когда всех сведений анкеты хватает для выполнения условий. Если нужны дата выдачи, срок действия, вид документа, конкретный разряд или иные отсутствующие сведения, оно должно быть `false`. Документы в приложении не загружаются: `achievementBasis:'self_reported'` прямо означает предварительный расчёт по заявленным данным. `requiresDocuments` сохраняется, чтобы напомнить о подтверждении при подаче. Олимпиадные права выводятся отдельно и не превращаются в произвольные числовые бонусы.

## Проценты

Ответ модели `chance`/`probability` не используется. Персональная вероятность `chance` остаётся `null`: для неё нужна проверенная и откалиброванная модель на данных о конкурсных группах, кандидатах и результатах зачисления. Одни проходные баллы не дают частоту будущих исходов конкретного абитуриента.

Реализован отдельный описательный показатель `historicalFit`. Он доступен при наличии минимум трёх разных сопоставимых лет с официальными результатами последнего зачисленного. Формат истории:

```json
{"value":280,"year":2025,"source":"https://university.ru/results/2025","type":"last_admitted","subjects":["Русский язык","Математика","Информатика"],"funding":"budget","competitionGroup":"09.03.01-очная-бюджет","campus":"Москва","maxScore":310,"includesAchievements":true,"budgetSeats":{"value":50,"year":2025,"source":"https://university.ru/results/2025","competitionGroup":"09.03.01-очная-бюджет","campus":"Москва"}}
```

Сравниваются только тот же конкурс, кампус, финансирование, тройка экзаменов и шкала 310 с достижениями. Для процентного показателя нужны известный конкурсный балл и совпадающее с текущим число бюджетных мест в каждом из учитываемых лет. Нужны выполненные минимумы, отсутствие дополнительных испытаний и положительное число мест. Неясные или конфликтующие записи за один год исключаются.

Формула — доля сопоставимых прошлых лет, в которые текущий расчётный балл был не ниже исторического проходного: `round(100 * matchingYears / totalYears)`. Например, один подходящий год из трёх — 33%. Это **не шанс поступления**, а описание найденной истории (`isProbability:false`). В интерфейсе показатель должен называться «Доля прошлых лет» или «Историческое сравнение», с числом наблюдений. Изменение правил достижений, состава конкурса и поведения абитуриентов ограничивает такую ретроспективу; результат нельзя называть прогнозом.

При недостаточных данных возвращается `historicalFit:null`, вместо вымышленного процента. `scoreMargin` показывает только разницу с последним проверенным историческим баллом и также не является вероятностью.

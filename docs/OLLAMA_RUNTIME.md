# Локальный Qwen через Ollama

Вызовы локальной модели не требуют ключа OpenAI/Yandex или оплаты API. Вычислительные ресурсы всё равно нужны: модель постоянно запускается на своём компьютере или сервере. Посетитель сайта обращается к Node API приложения, а не устанавливает Ollama у себя. Автономный HTML не содержит веса модели и сам локальную нейросеть не запускает.

Выбрана небольшая **`qwen2.5:0.5b`**: CPU подходит для первоначальной проверки, GPU не обязателен. На этой машине есть 32 GiB RAM и четыре CPU; runtime установлен без GPU-библиотек. Вариант 1.5B проверен и оказался слишком медленным на этом CPU, поэтому выбран 0.5B; пробная 1.5B удалена. Скорость и качество малого Qwen ограничены; правила поступления извлекаются только из предоставленных документов, арифметику проверяет код приложения.

## Linux AMD64: воспроизводимая установка

Нужны `bash`, `curl`, `sha256sum`, `tar`, `zstd`, `python3`. Скрипт не использует `sudo` и не исполняет скачанный shell-install script:

```sh
VOOOZ_OLLAMA_HOME=/workspace/.voooz-ollama bash scripts/setup-ollama.sh install
```

Он скачивает официальный релиз **Ollama 0.40.9** с GitHub, проверяет опубликованный SHA256 (`01f0d0ae50cad3295a79a165033a65cf324f8ae5f7be64679464d29ecf28d67c`), извлекает бинарник и CPU-библиотеки. Большой архив (~1.5 GB, включает GPU-компоненты) после проверки/установки удаляется; CPU runtime занимает около 72 MiB. При повторном запуске установленная версия используется повторно. По умолчанию, без `VOOOZ_OLLAMA_HOME`, файлы находятся в игнорируемой `.cache/ollama` проекта. Ни runtime, ни веса не коммитятся.

В отдельном постоянно работающем процессе:

```sh
VOOOZ_OLLAMA_HOME=/workspace/.voooz-ollama bash scripts/setup-ollama.sh serve
```

Запуск ограничен `127.0.0.1:11434`, `OLLAMA_NO_CLOUD=1`, одной параллельной генерацией и одной загруженной моделью. Модели хранятся в указанном каталоге `models`. При первом `serve` upstream Ollama дополнительно создаёт свои служебные файлы `~/.ollama/id_ed25519` и `.pub`; домашний каталог процесса должен разрешать эту запись. Это локальная идентичность Ollama, а не платный API-ключ. `HOME` скрипт не переопределяет. В песочнице разрешение на эту конкретную папку нужно предоставить отдельно.

В другом терминале загрузите модель, проверьте её наличие и выполните настоящий короткий запрос:

```sh
VOOOZ_OLLAMA_HOME=/workspace/.voooz-ollama bash scripts/setup-ollama.sh pull
VOOOZ_OLLAMA_HOME=/workspace/.voooz-ollama bash scripts/setup-ollama.sh check
VOOOZ_OLLAMA_HOME=/workspace/.voooz-ollama bash scripts/setup-ollama.sh smoke
```

`check` проверяет установленную `qwen2.5:0.5b` через `/api/tags`. `smoke` требует завершённую реальную генерацию JSON через `/api/chat`; открытый порт и `/api/version` сами по себе её не заменяют. Для другой установленной модели укажите `OLLAMA_MODEL`; та же модель должна быть выбрана в настройках приложения. На Windows/macOS используйте официальный установщик Ollama, затем `ollama pull qwen2.5:0.5b`.

## Сеть и текущее состояние

Проверка 23.10.2026: официальный GitHub-релиз скачан, SHA256 совпал, CPU runtime установлен. Сервер запущен; `/api/version` возвращает HTTP 200 и `0.40.9`. Модель `qwen2.5:0.5b` успешно загружена; `check` подтверждает её наличие, а `smoke` выполнил настоящую локальную генерацию и получил завершённый JSON `{"ok":true}`. Это проверка реальной модели, отдельно от автоматических тестов с тестовым провайдером. Дополнительно POST /api/recommendations с настоящей Qwen и контрольным искусственным документом завершился за 43 секунды, ai.used:true; программа не была полностью подтверждена, поэтому competitionScore остался null. Этот контрольный пример не подтверждает актуальные условия какого-либо реального вуза.

Первоначальная загрузка блокировалась сетевым прокси (`CONNECT 403`). Реестр доступен по `registry.ollama.ai`; по фактическому перенаправлению установлен точный хост весов `dd20bb891979d25aebc8bec07b2b3bbc.r2.cloudflarestorage.com`. После разрешения доступа модель скачана. В черновике среды сохранены оба хоста; сохранение черновика не равно применению постоянной конфигурации. Для будущих задач нужно сохранить настройки и опубликовать среду. После загрузки генерации не нужен доступ к реестру; получение актуальных данных вузов отдельно требует доступа к их официальным сайтам. На этой машине сайты вузов всё ещё могут блокироваться сетевой политикой, и это не заменяется памятью модели.

Во время первоначального запуска была предоставлена запись в фактическую служебную папку `/home/agent/.ollama`. Обычный процесс видел домашний каталог как read-only; запуск проверенного helper через поддерживаемый sandbox escalation с одобренным доступом позволил создать локальную идентичность. Не требуется менять `HOME`, отключать TLS или обходить сетевой прокси. В новой машине при отсутствии служебной папки эту необходимость нужно проверить заново.
